# Three-arm common-horizon pilot

Status: registered implementation pending real execution/audit; no outcome claim.

Six serial episodes compare no maintenance, compact at horizon start and compact
at midpoint, followed by reverse order. Every episode uses a fresh isolated clone
of the verified SF1 source, the same SHA-pinned113 actual Snowset arrivals, declared
four-template benchmark mapping, one FIFO query client and60-second horizon.
The horizon inherits the audited source-bin queue screen. The midpoint is a
transparent experimental candidate, not a model output, optimal delay or hidden
policy rule. Two episodes/arm screen completeness/repeatability, not sample power.

All arrivals and residual queue identities remain. No post-horizon dispatch or
cancellation; in-flight queries and rewrites finish naturally. Actual maintenance
start/duration/bytes/snapshot transition, completed task-lifetime overlap and
query snapshot/service/queue/boundary outcomes are audited from raw statements,
telemetry and engine responses. No requirement to manufacture positive overlap.
Initial/final snapshots each pass exact bidirectional multiset comparison to the
source and expected query results. Cohort gate compares initial file row/byte
multisets across all episodes; equality does not prove equal cache/locality.

Every arm performs metadata checkpoints at start/midpoint. Changed-state arms
also need actual post-commit metadata publication and query-session refresh;
these recorded overheads differ and prevent a pure engine-only causal claim.
Each query pins the latest available controller snapshot, with state availability
and possible publication lag retained. Strict two-second actual action metadata /
telemetry gates remain. Own recorded metadata work is allowed alongside treatment
queries; unrelated Spark work remains forbidden. This change is needed to measure
complete action schedules, rather than treating all intentional maintenance as
foreign contamination. Original queue-only audit retains its stricter null scope.

The coordinator pins code/config and checks every real episode and frozen raw
post-run audit before the next. Documentation-only commits may sync during the
cohort; any code/protocol change stops dependent episodes. Failed/no-op/late or
mismatched-layout attempts remain, and the remaining count is explicit. No retry
until an attractive effect occurs. No tables/data or services are removed/stopped.

Report completed throughput, unfinished queue, actual latency/queue distributions,
maintenance progress and residual layout separately. No arbitrary scalar penalty,
SLA, counterfactual label, independent calibration or cost-training approval is
introduced. Valid model training still needs larger independent blocks and
registered splits; publication still needs forecast benefit, baselines, broader
workloads/scales and uncertainty. Pilot outcomes will decide the next collection
rather than weakening gates to fit six observations.
